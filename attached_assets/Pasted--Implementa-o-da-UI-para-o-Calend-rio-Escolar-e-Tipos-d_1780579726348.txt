 Implementação da UI para o Calendário Escolar e Tipos de AvaliaçãoObjetivo: Desenvolver a camada de interface (UI/UX) para o módulo de Calendário e Avaliações, conectando as tabelas e rotas já existentes na Base de Dados (DB) ao Perfil de Gestão do Colégio.1. Tela de Configuração: Tipos de Prova / Avaliação (CRUD UI)Ação: Criar a interface para gerir os tipos de avaliação que alimentam o calendário.Componentes de UI:Tabela de Tipos: Listagem limpa exibindo os modelos cadastrados na DB (ex: Prova do 1º Trimestre, Prova Escrita, Trabalho de Campo, Exame Nacional).Badges de Peso Pedagógico: Exibir ao lado de cada tipo de prova o seu peso na nota final (ex: Peso 1, Peso 2, Peso 3) usando etiquetas visuais coloridas.Formulário Modal: Janela sobreposta para adicionar/editar tipos de prova com inputs para: Nome da Avaliação, Sigla (ex: P1, ATT), Peso Académico e Cor de Identificação no Calendário.2. Interface Principal: O Calendário Escolar DinâmicoComponente de Visualização (Calendário): Implementar uma biblioteca de calendário (ex: FullCalendar ou similar) integrada no ecossistema do projeto.  Alternadores de Visão (Tabs): No topo do calendário, permitir que o gestor mude o modo de exibição com um clique: [ Mês ], [ Semana ] ou [ Lista / Agenda ].Filtros Rápidos Laterais ou de Topo: Para evitar a poluição visual, o utilizador deve conseguir filtrar os eventos exibidos por:Curso / Classe (ex: 10ª Classe - Ciências Económico-Jurídicas).Turma (ex: Turma A, Turma B).Categoria de Evento (ex: Apenas Provas, Feriados/Eventos Sociais, Reuniões de Pais).3. Fluxo de Agendamento de Provas (UI/UX)Ação de Clique Direto: Ao clicar num dia vazio do calendário, o sistema deve abrir o modal "Agendar Avaliação".  Campos do Modal de Agendamento:Dropdown de seleção do Tipo de Prova (puxando os dados configurados no ponto 1).Dropdown de seleção da Disciplina (ex: Matemática, Língua Portuguesa, Física).Seletores de Turma(s) (com opção de seleção múltipla se a prova for geral para toda a classe).Campos de Hora de Início e Hora de Fim.Campo de texto para Notas/Instruções Adicionais (ex: "Trazer calculadora científica").4. Requisitos de Frontend e Feedback VisualEventos Codificados por Cores (Color-Coded): As avaliações devem aparecer na grelha do calendário com a cor de fundo correspondente ao seu tipo (ex: Provas a Vermelho, Trabalhos a Azul, Feriados a Verde) para leitura visual imediata.Responsividade: A visão em formato "Lista / Agenda" deve ser o padrão automático quando o ecrã for detetado como mobile, garantindo que os coordenadores consigam consultar e alterar datas pelo telemóvel.Validação de Erros em Tela: Se o utilizador tentar agendar duas provas para a mesma turma no mesmo horário, a UI deve disparar um alerta (Toast Notification) de conflito antes de enviar a requisição para a API.
