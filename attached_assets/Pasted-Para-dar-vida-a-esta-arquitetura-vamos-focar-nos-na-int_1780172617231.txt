Para dar vida a esta arquitetura, vamos focar-nos na **integração do GPO via Webframe** utilizando a **API REST da EMIS**.
O segredo desta integração está no backend: ele precisa de recolher os parâmetros parametrizados no Backoffice, gerar um identificador único de transação (MerchantReference), calcular a assinatura digital (**HMAC-SHA256**) para garantir que os dados não foram adulterados, e devolver o payload que o frontend usará para abrir o Webframe.
Abaixo, encontras um exemplo prático em **Node.js (TypeScript)** que ilustra este racional, seguido do mapeamento dos campos obrigatórios.
## 1. Exemplo de Código (Backend - Node.js/TypeScript)
```typescript
import crypto from 'crypto';
import axios from 'axios';

// Interfaces baseadas nas configurações guardadas no Backoffice
interface TechnicalConfigs {
    gpoApiUrl: string;       // Definido no menu "Parametrização" (Ex: https://gateway.emis.co.ao/api/v1)
    merchantId: string;      // Definido no menu "Configurações Técnicas"
    terminalId: string;      // Definido no menu "Configurações Técnicas"
    secretKey: string;       // Definido no menu "Configurações Técnicas" (usado para o Hash)
    urlSuccess: string;
    urlFail: string;
}

interface PaymentRequest {
    amount: number;          // Valor da compra (Ex: 1500.50)
    currency: string;        // Moeda (AOA para Angola)
    orderId: string;         // ID interno da fatura do teu sistema
}

export class EmisGpoService {
    private configs: TechnicalConfigs;

    constructor(configs: TechnicalConfigs) {
        this.configs = configs;
    }

    /**
     * Gera a assinatura HMAC-SHA256 obrigatória pela EMIS para validar a mensagem
     */
    private generateHmacSignature(payload: string): string {
        return crypto
            .createHmac('sha256', this.configs.secretKey)
            .update(payload)
            .digest('hex');
    }

    /**
     * Prepara a transação e solicita o token de inicialização do Webframe à EMIS
     */
    async initiateWebframePayment(payment: PaymentRequest) {
        const merchantReference = `TX-${payment.orderId}-${Date.now()}`;
        
        // 1. Montagem do Payload com os campos obrigatórios da EMIS
        const eMisPayload = {
            merchantId: this.configs.merchantId,
            terminalId: this.configs.terminalId,
            merchantReference: merchantReference,
            amount: payment.amount,
            currency: payment.currency, // "AOA"
            returnUrlSuccess: this.configs.urlSuccess,
            returnUrlFail: this.configs.urlFail,
            timestamp: new Date().toISOString()
        };

        // 2. Cálculo do Checksum de segurança (Assinatura)
        const stringToSign = `${eMisPayload.merchantId}${eMisPayload.terminalId}${eMisPayload.merchantReference}${eMisPayload.amount}${eMisPayload.timestamp}`;
        const signature = this.generateHmacSignature(stringToSign);

        try {
            // 3. Disparo contra a API configurada no menu Parametrização
            const response = await axios.post(
                `${this.configs.gpoApiUrl}/transactions/init-webframe`, 
                eMisPayload, 
                {
                    headers: {
                        'Authorization': `Bearer ${signature}`, // Exemplo de envio de assinatura por Header
                        'Content-Type': 'application/json'
                    }
                }
            );

            // A EMIS responde com o Token da sessão do Webframe e a URL oficial
            return {
                sucesso: true,
                transactionId: response.data.id,
                webframeUrl: response.data.redirectUrl, // URL que o Frontend vai injetar no iframe
                merchantReference
            };

        } catch (error: any) {
            return {
                sucesso: false,
                erro: error.response?.data?.message || 'Falha na comunicação com o Gateway EMIS'
            };
        }
    }
}

```
## 2. Campos Obrigatórios para a Integração EMIS (GPO)
Quando o teu código comunica com a API da EMIS para iniciar o Webframe, estes são os campos que **não podem faltar** no JSON e que devem ser alimentados pelas tuas tabelas de parametrização e de vendas:
| Campo Técnico | Tipo | Origem no Sistema | Descrição |
|---|---|---|---|
| **merchantId** | String | Configurações Técnicas (Admin) | Identificador único da tua empresa fornecido pela EMIS. |
| **terminalId** | String | Configurações Técnicas (Admin) | Identificador do terminal virtual que processa a venda. |
| **merchantReference** | String | Motor de Vendas (Backend) | Código único da transação gerado pelo teu sistema (essencial para a reconciliação). |
| **amount** | Decimal | Carrinho de Compras | O valor total a ser cobrado ao cliente. |
| **currency** | String | Fixo / Configuração | Código ISO da moeda. Para a rede Multicaixa, o padrão obrigatório é **AOA**. |
| **returnUrlSuccess** | String | Configurações Técnicas (Admin) | URL do teu site para onde o cliente é redirecionado após pagar com sucesso no Webframe. |
| **returnUrlFail** | String | Configurações Técnicas (Admin) | URL do teu site caso o pagamento falhe ou seja cancelado. |
| **timestamp** | String | Backend (Tempo Real) | Data/Hora no formato ISO 8601 para evitar ataques de *replay* de transações. |
| **signature / hash** | String | Função Criptográfica | O resultado do emparelhamento dos dados acima com a **Secret Key** do Admin através de HMAC-SHA256. |
## 3. O Fluxo de Teste de Conectividade (Botão no Backoffice)
Para cumprir o requisito de **"Testar Conectividade"** solicitado na tua nota, o teu desenvolvedor deve expor um endpoint simples no backend que utilize as funções acima para disparar um método GET ou POST de diagnóstico (como o endpoint /status ou /echo da própria API da EMIS).
Se a EMIS responder com HTTP 200, o painel pinta o botão a verde; se der HTTP 401 Unauthorized, o admin sabe que errou na chave secreta ou nos IPs parametrizados.
