O que é o SDD
O SDD permite que empresas (Credores) cobrem automaticamente os seus clientes (Devedores) através de débito direto nas contas bancárias, sem necessidade de o cliente iniciar cada pagamento manualmente.

Fluxo Principal do SDD
Credor                    EMIS                    Banco Devedor
  │                         │                          │
  │── Registo Mandato ──────►│                          │
  │                         │── Validação Mandato ────►│
  │                         │◄─ Confirmação ───────────│
  │◄─ Mandato Ativo ────────│                          │
  │                         │                          │
  │── Ficheiro PAIN.008 ───►│                          │
  │   (Instrução Débito)    │── Débito na Conta ──────►│
  │                         │◄─ Resultado ─────────────│
  │◄─ PAIN.002 (Status) ────│                          │

Componentes que domino
1. Gestão de Mandatos

Criação e registo de mandatos
Alteração e cancelamento
Validação de assinaturas
Controlo de estado (ACTV, CANC, SUSP)

2. Ficheiros ISO 20022

PAIN.008 — Instrução de débito direto
PAIN.002 — Relatório de estado de pagamento
PAIN.007 — Reversão de débito

3. Ciclos de Processamento

Pré-notificação ao devedor
Janelas de submissão (D-1, D-2)
Tratamento de rejeições e devoluções
Reapresentação de cobranças

4. Reconciliação

Matching de instruções vs resultados
Tratamento de R-transactions (RJCT, RTRN, REFD)
Relatórios de liquidação

REGRAS DO BACKEND MONOLÍTICO

Tudo o que é lógica de negócio, estado, orquestração e decisão fica no backend.


✅ 1.1 — Máquina de Estados do Mandato
→ Backend
O backend é o único dono do estado do mandato. O motor de pagamentos não decide estados — apenas executa e reporta resultados.
Backend controla:
- Criação do mandato (PENDING)
- Activação após confirmação do motor (ACTV)
- Suspensão/Cancelamento com base nos códigos de retorno
- Expiração por job noturno (36 meses sem uso)
- Registo de auditoria de cada transição

✅ 1.2 — Sequência de Cobrança (FRST/RCUR/FNAL/OOFF)
→ Backend
O backend determina qual sequência usar com base no histórico do mandato. Envia essa informação ao motor como parâmetro da instrução.
Backend decide → Motor executa com a sequência recebida

✅ 1.3 — Cálculo da Janela de Submissão
→ Backend
O backend calcula a data correcta de submissão (D-2 / D-1 em dias úteis) e agenda o envio ao motor. O motor não conhece regras de calendário angolano.
Backend calcula:
- Dias úteis (excluindo feriados angolanos)
- Data limite de submissão por tipo de sequência
- Bloqueio se passou o cutoff_time
- Reагendamento automático para próximo ciclo

✅ 1.4 — Pré-Notificação
→ Backend

✅ 1.6 — Tratamento de R-Transactions
→ Backend

✅ 1.7 — Reconciliação Diária
→ Backend
O backend faz o matching entre o que enviou ao motor e o que foi confirmado. O motor apenas fornece o ficheiro de resultados (PAIN.002).
Backend executa:
- Job diário após recepção do PAIN.002
- Matching instrução enviada vs resultado recebido
- Actualização de faturas/saldos (apenas ACSC)

- Geração do relatório de reconciliação

→ Backend
Toda a validação de negócio ocorre no backend antes de qualquer envio ao motor.

- Mandato ACTV
